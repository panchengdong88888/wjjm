# MainLeftBottom(2).lua 明文恢复工程

本仓库是该 Lua VM 反虚拟化与作者级可读 Lua 恢复工作的**唯一主工作区**。后续 AI 对话应先读取本文件，再按下方顺序读取接续文档；不应从头重复已经完成的静态分析。

## 防上下文中断
每批次完成后立即提交检查点，不等上下文接近上限。具体强制流程见 docs/handoff/10_防上下文中断_checkpoint协议.md。每次新对话先读取最新机器状态 JSON 与检查点协议。

## 新对话接续顺序
1. `docs/handoff/00_新对话先读.txt`
2. `docs/handoff/01_原始资料校验与总账.md`
3. `docs/handoff/05_机器可读接续状态.json`
4. `02_基础索引/02_原型总索引.json`、`02_基础索引/03_函数状态清单.csv`、`docs/handoff/04_闭包捕获映射.json`
5. `03_静态反汇编/` 下 corrected phase3 反汇编、控制流报告，以及指令级去虚拟化清单。
6. 先读取 `docs/handoff/11_新框架API映射.md`，再检查 `04_源码候选/MainLeftBottom_恢复源码.lua` 与其他候选，明确区分“静态候选”“指令级清单”和“作者级普通 Lua”。

## 目录
- `01_原始资料/`：用户原始加密 Lua。
- `02_基础索引/`：VM dump、原型索引、函数状态、opcode 参考。
- `03_静态反汇编/`：物理 PC 校正反汇编、阶段三报告、指令级去虚拟化清单。
- `04_源码候选/`：尚未全部验证的普通 Lua 候选；`MainLeftBottom_恢复源码.lua` 是集中候选汇总稿，不是已验证可运行脚本。
- `docs/handoff/`：跨对话接续说明、总账、闭包映射、机器状态、SHA256；`11_新框架API映射.md` 是引擎接口对照依据；`13_MainLeftBottom_原型结构树.md` 汇总110个原型的父子层级和捕获元数据。
- `05_历史草稿/`：旧轮次草稿和审计，作为参考，不作为权威身份来源。

## 当前技术事实
- 原型 110 个，物理指令 5,580 条，实际 opcode 356 种，范围 1..412。
- 指令记录格式 `[FLAG, OPCODE, A, B, C]`；FLAG 不是 opcode。
- 新分析统一使用 JSON 零基路径 `root.children[n]`。旧反汇编 `root/46` 等一基标签必须先转换。
- 765KB 指令级去虚拟化清单不是作者原始 Lua，也不可直接运行。
- 最终目标是可读、可维护的作者级普通 Lua；不得把猜测当作已验证变量名或源码。

## 资料完整性说明
