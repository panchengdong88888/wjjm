# 检查点 #31：DiuItems 深层静态审计（控制流与业务数据流第一轮）

日期：2026-11-09  
原型：`root.children[46]` / legacy `root/47` / `DiuItems`  
物理指令：169；常量：64；子原型：1（关键词匹配闭包 20 条指令）

## 捕获身份

由 root PC64 创建 DiuItems：
- UP[0] 捕获父 root T[2]。函数入口读取/设置 `isDiuing`，所有早退和正常结束路径都会将其复位为 false。可确定语义为共享丢弃状态表。
- UP[1] 捕获父 root T[5]。函数中用于输出进度、错误和完成通知，可确定语义为通知回调。
- 子闭包 `root.children[46].children[0]` 捕获 DiuItems 的 T[5]，即关键词数组。

## 已闭合的入口和早退路径

1. 若共享状态表 `isDiuing` 为真，直接返回，阻止重复执行。
2. 设置 `isDiuing = true`。
3. 调用 `GetDroppedItems()`，接收两个返回值。
4. 若第二个返回值缺失/false，按 0 处理。
5. 比较地面物品数量与常量 35；超过 35 时，通知：
   `地面物品({count})超过上限(35)`
   随后复位 `isDiuing=false` 并返回。
6. 读取 `SL:GetMetaValue("BAG_DATA")`。若无背包数据，复位状态并返回。

## 关键词闭包与列表

父函数构造以下 28 项关键词表：
`声望卷、称号卷、悟道茶、转生水晶、时装晶魄、血龙宝珠、洗髓丹、恶魔令牌、晶石、经验卷、技能残页、熬光、敖顺、敖闰、点点、之力、复活、麻痹、护身、主印、副印、神凤、龙傲、冰雪、上古、起源、残、鸿蒙`

子闭包遍历关键词数组，对物品名称调用：
`string.find(itemName, keyword, 1, true)`
最后一个参数为 true，表示 plain literal search；命中任意关键词即返回 true，遍历完未命中返回 false。

## 背包扫描已确认的过滤条件

父函数以 `pairs(BAG_DATA)` 遍历背包数据；候选条目要求：
- 条目值存在；
- `item.Name` 存在；
- `item.MakeIndex` 存在；
- 调用 `SL:GetMetaValue("ITEM_IS_BIND", item)` 后，绑定判定不得为真。

随后通过关键词闭包检查名称，并在候选列表中建立记录，至少包含：
- `makeIndex = item.MakeIndex`
- `count = item.OverLap or 1`
- `Name = item.Name`
- `name = item.Name`

注意：PC89–98 的寄存器 R4 条件跳转及关键词闭包调用路径存在一处需要进一步核对的控制流问题。当前线性反汇编显示 R4 在 PC36 被赋值为 1，但必须结合原始融合载荷和分支目标再次核实它在 PC89 的实际值及其条件语义。因此目前不将“关键词命中/未命中时是否加入候选列表”写成最终结论。

## 丢弃循环与消息结构（已确认部分）

- 候选列表为空时，通知 `背包无可丢弃物品`，复位状态并返回。
- 处理候选列表时，使用 35 作为数量上限；达到上限时通知 `地面物品已满{count}件，停止丢弃`，再转到汇总通知。
- 单项处理时，先通过回调输出 `丢: {name}`。
- 随后调用 `LuaSendMsg`，消息类型为 `global.MsgType.MSG_CS_MAP_ITEM_DISCARD`。消息字段来自候选记录的 `makeIndex`、`count`、`name`，另含两个数值 0 和 `string.len(name)`。
- 成功处理计数递增；循环结束通知 `共丢弃 {count} 件物品`，最后复位 `isDiuing=false`。

## 当前状态

这是深层静态审计检查点，不是完整普通 Lua 恢复。关键未闭合点：
1. PC89–98 的条件分支与 R4/R14 寄存器生命周期；
2. 候选表实际构造的精确字段、插入参数和关键词命中分支；
3. LuaSendMsg 的精确实参顺序及是否还包含隐藏的接收者/协议字段；
4. PC128–160 计数器与迭代器终止条件的逐条闭合。

因此 DiuItems 不计入完整静态恢复数；运行时验证仍为 0。
