# 检查点 #28：PickUpItems 主函数第一轮控制流与数据流核验

日期：2026-11-09  
原型：`root.children[21]` / legacy `root/22` / `PickUpItems`  
物理指令：172；常量：34；子原型：2（两个比较闭包已在检查点 #26 恢复）

## 本轮处理范围

逐条复核了 root/22 的 172 条物理指令、raw VM dump、当前 opcode reference 中相关操作码语义，以及两个子闭包的调用位置。此检查点是主函数的控制流/数据流分析，不是完整普通 Lua 恢复，不增加完整静态恢复计数。

## 已确认的入口和早退

- PC1–3：建立局部表，并调用 `GetDroppedItems()`，接收两个返回值。
- PC4：检查第二个返回值是否等于数值 0。
- 若为 0，PC6–8 通过捕获回调发送 `地面无可拾取物品`，PC9 直接返回。
- 否则 PC10–11 调用 `PlayerPos()`，接收两个坐标值。

## 掉落物字段兼容读取

在逐个遍历掉落物时，主函数按以下优先级读取字段：

- 名称：`mName` → `mONameStr` → `Name` → `name` → 空字符串。
- X：`mCurrMapX` → `MapX` → `mapX` → `x`。
- Y：`mCurrMapY` → `MapY` → `mapY` → `y`。

PC51–54 对最终 X、Y 值分别做 truthiness 检查；任一缺失/false 时跳过当前物品，进入外层迭代的下一项。

## 距离计算

PC55–63 的算术和调用链可确定为曼哈顿距离：

```lua
dist = math.abs(playerX - itemX) + math.abs(playerY - itemY)
```

这里不是欧几里得距离，没有平方和或开方。

## 列表构造、排序与合并

- PC12–13 初始化两个列表。
- PC104–109 对其中一个列表调用 `table.sort(list, Nested_dist)`。
- PC110–114 对另一个列表调用 `table.sort(list, Nested_dist_2)`。
- 第一个比较器按 `kIdx` 升序，相同 `kIdx` 时按 `dist` 升序。
- 第二个比较器按 `dist` 升序。
- PC115 初始化合并结果列表；PC116–137 依次遍历两个排序列表，将元素追加到结果列表。
- PC138–141 检查合并结果长度；空列表时直接返回。

### 仍需解决的关键疑点

PC65–81 有一段以局部空表 R0 为输入的 `ipairs` 遍历，期间涉及字符串查找、索引值和两个列表分流。按当前 VM dump，R0 在入口处由 OP_009 创建为空表，且这段路径内未发现给 R0 写入元素的指令；但需要继续核对融合载荷、寄存器别名及 CFG 跳转边，才能判断这段循环是否确实恒为空、是否是无效/混淆代码，或当前反汇编对寄存器作用域的表达仍有遗漏。因此暂不简化或删除该段逻辑，也不将两个列表的业务分类写成确定结论。

## 选取与移动

- PC142–147：从合并结果列表取首项，调用 `MoveTo(item.x, item.y, 0)`。
- PC148–161：分别计算玩家当前位置与目标坐标的 X/Y 绝对差，并分别与 1 比较；任一轴差值大于 1 时跳过拾取调用。
- PC162–165：解析 `global.dropItemController.PickMainPlayerPosItem` 并以 controller 作为 self 调用。
- PC166–171：读取捕获回调，拼接 `拾取: ` 与目标记录中 `item.mName`，将消息传给该回调。
- PC172：函数尾部 return。

## 当前结论

已高置信确定入口早退、字段兼容优先级、坐标缺失跳过、曼哈顿距离、两组排序/合并框架、最近项移动、1 格邻近判定、拾取控制器方法及通知文本。

尚未闭合：PC65–101 的列表分流与 R0/R16/R17/R18 等寄存器实际角色；需解析融合调用参数窗口及全部跳转边。故 `PickUpItems` 仍是待恢复主函数，不能计入完整静态恢复。
