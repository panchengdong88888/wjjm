## 三、关键纠错：onDamageMsg 与 InstallDamageHook 不可混用

两个原型的作用和父寄存器生命周期不同：

1. PC357创建`onDamageMsg`，捕获T[41] blacklistState；PC359将其写入`MainLeftBottom.onDamageMsg`。它负责解析伤害消息、过滤自身/分身等情况并记录`lastAttacker`。
2. PC360创建`InstallDamageHook`，捕获T[0]=MainLeftBottom.a与T[4]=PrintLog；其闭包负责挂接消息处理器，并在处理器包装闭包内按需调用`gameMapController.onDamageMsg`。
3. PC360覆写父T[57]为InstallDamageHook；PC368的BlacklistPlayerDetection捕获的是该T[57]共享cell。
4. 因而BlacklistPlayerDetection.UP[1]必须指向`rootCells[57]`，且cell当前值必须是InstallDamageHook，不能接成onDamageMsg。

主恢复稿已有T[57]唯一cell断言，本批再次增加以下跨字段/跨导出身份保护：
- `rootModule.blacklist == rootSource.blacklistState`
- `rootModule.onDamageMsg == rootPrototypes.onDamageMsg`
- `rootCells[57].value == rootPrototypes.InstallDamageHook`
- `rootCells[57].value ~= rootPrototypes.onDamageMsg`
- `_G.BlacklistItems == rootPrototypes.BlacklistPlayerDetection`
- `_G.ClearBlacklistItems == rootPrototypes.ClearBlacklistItems`

这些assert属于恢复适配层，不是原作者Lua语句。

## 四、函数主体来源与边界

- GetMapData2DPtr：`04_源码候选/root22_GetMapData2DPtr.lua`。可达PC1-PC37执行五参数有效性判断、相同坐标返回0、Chebyshev距离计算及距离上限判断；PC38-PC144为无可达入口尾部；UP0捕获表在可达路径未读取。
- PCallHelper_2：`04_源码候选/代理与回调短函数_第四批.lua`。无参pcall执行Nested_FriendProxy，失败或false/nil归一为nil。
- FindBlacklistPlayer：`04_源码候选/root49_PCallHelper_2_and_root51_FindBlacklistPlayer.lua`。先查目标ID，再按ACTOR_MASTER_ID回查主人ID。
- UseItemByIndex：`04_源码候选/短函数草稿_第三十一批.lua`。遍历捕获的物品名称，查询索引和数量，满足条件调用SL:UseItemByIndex。
- onDamageMsg：`04_源码候选/root52_onDamageMsg.lua`。pcall保护JSON解码，过滤主角色、自身攻击者、无效名称和“分身”，写入共享lastAttacker。
- InstallDamageHook：`04_源码候选/短函数草稿_第三十九批.lua`。检查控制器/消息表/消息类型/原处理器，幂等挂接包装器；包装器pcall可选onDamageMsg后返回原处理器结果。
- DeathAutoBlacklist：`04_源码候选/root25_DeathAutoBlacklist.lua`。消费并清空lastAttacker，排除已在黑名单者，否则按0至2.5秒、每0.5秒一次发出六次加黑请求。
- BlacklistPlayerDetection：`04_源码候选/root47_BlacklistPlayerDetection.lua`。216条物理指令的主体已静态恢复；使用UP1安装伤害钩子，处理HP死亡边沿、白名单和视野玩家，按配置距离/节流/传送物品处理黑名单目标。
- ClearBlacklistItems：`04_源码候选/短函数草稿_第五十四批.lua`。获取FriendProxy并遍历黑名单条目，按序请求移除并删除数据，最后清空lastAttacker。

注意：本批只核对根模块闭包创建与捕获接入，不重新声称上述主体已运行时验证，也不把引擎对象方法的内部实现纳入脚本恢复范围。
