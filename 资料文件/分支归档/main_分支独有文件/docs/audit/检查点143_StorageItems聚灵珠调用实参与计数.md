# 检查点 #143：StorageItems 聚灵珠子原型调用实参与存仓计数

日期：2026-11-09  
原型：`root.children[50]` / legacy `root/51`

## 本批确认

### 1. PC167-PC170 子原型0调用实参

父函数PC102创建子原型0（`root/51/1`），PC167-PC170执行二参数调用。寄存器数据流对应：

- 第一个实参：当前 `BAG_DATA` 物品记录，父函数R19。
- 第二个实参：R8特殊名称表当前 `ipairs` 迭代项，父函数R25。

这一身份与子原型内部实现相符：第二参数用于 `string.find(arg2, "聚灵珠", 1)`；命中后以第一个参数作为物品对象，读取Name、StdMode、Dura、DuraMax并输出详情。因此子原型0并非对背包物品做无条件检查，而是在当前物品与当前特殊名称项命中后调用。

### 2. PC211 存仓计数

PC211为 `R13 = R13 + 1`。它位于LuaSendMsg发送路径之后；PC218-PC223随后使用R13拼接“存仓完成, 共存入 N 件物品”提示。因此R13是本轮成功走完存仓发送路径的计数，每条发送路径递增1，不是物品堆叠数量。

### 3. 仍未闭合

- 子原型1（`root/51/2`）27条指令的容量算术，尚未得到可靠的逐寄存器最终表达式。
- PC206-PC210包含连续融合载荷。当前校正反汇编仅显示融合语义模板，未完整给出每条载荷子指令各自的寄存器操作数；不能用外层首条指令的A/B/C冒充所有融合子指令的操作数。
- LuaSendMsg第4实参来自子原型1返回值，但协议字段含义尚未映射。
