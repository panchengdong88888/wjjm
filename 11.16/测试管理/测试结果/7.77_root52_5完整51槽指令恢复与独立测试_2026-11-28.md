## 四、51槽控制流逐段恢复

### 4.1 外层三组、内层配置遍历（槽1–21）

- 槽1装载全局`ipairs`。
- 槽2 Opcode76融合消费槽3：创建外层数组并装入H[0]；槽4、5分别装入H[1]、H[2]；槽6 Opcode41将三项填入数组。
- 槽7 Opcode307调用`ipairs({H[0],H[1],H[2]})`，建立外层迭代器。
- 槽8跳转至槽20，先取得第一组。
- 槽9 Opcode188融合消费槽10：装载`ipairs`并复制当前组；槽11 Opcode386建立当前组的内层迭代器。
- 槽12跳至槽18开始内层迭代。
- 槽13读取当前配置的`key`；槽14 Opcode294与第一个显式参数`buttonKey`比较。
- key不匹配时，槽15跳过状态写入，进入内层迭代推进。
- key匹配时，槽16保存当前配置，槽17执行`buttonConfig.toggled = toggled`。
- 槽18 Opcode250推进内层ipairs；槽19回到槽13。
- 槽20 Opcode122推进外层ipairs；槽21回到槽9处理下一组。

**重要控制流结论：匹配后没有break或return。** 三组配置都会遍历完；每个匹配项都会写入toggled，最后一个匹配项保存在局部配置寄存器中。不能照搬11.9旧版“命中后立即return”的写法。

### 4.2 查找控件并检查更新条件（槽22–30）

- 槽22 Opcode232融合消费槽23：从H[3]取得按钮映射表，并按`buttonKey`读取按钮。
- 槽24/25：按钮不存在则直接结束。
- 槽26/27：没有匹配到配置则直接结束。
- 槽28–30：匹配配置的`toggle`字段不存在/为假时直接结束。

因此，配置的toggled写入发生在控件查找之前；即使按钮不存在，匹配配置仍已被写入toggled。若配置没有toggle文案，也会保留toggled写入，但不更新GUI。

### 4.3 更新标题和颜色（槽31–51）

- 槽31装载全局GUI。
- 槽32 Opcode204准备`Button_setTitleText`方法receiver/self；槽33装入按钮对象。
- 槽34–39按第二个参数`toggled`选择标题：真时使用`buttonConfig.toggle`，假时使用`buttonConfig.name`。
- 槽40 Opcode128执行方法调用。
- 槽41 Opcode210融合消费槽42、43：重新装载GUI、准备`Button_setTitleColor`方法receiver/self，并装入按钮对象。
- 槽44–49按toggled选择颜色：真时`#ff0000`，假时`#ffffff`。
- 槽50 Opcode128执行颜色方法调用；槽51 Opcode205结束函数。

两处方法调用都包含GUI receiver/self，Lua表达必须使用冒号调用：
- `GUI:Button_setTitleText(button, title)`
- `GUI:Button_setTitleColor(button, color)`

## 五、还原后的可读Lua闭包形态

以下外层工厂是源码层的词法捕获适配；其返回的内层函数才对应原始`root/52/5`原型（2个显式参数、4项upvalue）：

```lua
local function MakeButtonToggleStateSync_11_16(
    firstGroup,
    secondGroup,
    thirdGroup,
    visibleItems
)
    return function(buttonKey, toggled)
        local buttonGroups = { firstGroup, secondGroup, thirdGroup }
        local matchedConfig

        for _, buttonGroup in ipairs(buttonGroups) do
            for _, buttonConfig in ipairs(buttonGroup) do
                if buttonConfig.key == buttonKey then
                    matchedConfig = buttonConfig
                    buttonConfig.toggled = toggled
                end
            end
        end

        local button = visibleItems[buttonKey]
        if not button then
            return
        end
        if not matchedConfig then
            return
        end
        if not matchedConfig.toggle then
            return
        end

        GUI:Button_setTitleText(
            button,
            toggled and matchedConfig.toggle or matchedConfig.name
        )
        GUI:Button_setTitleColor(
            button,
            toggled and "#ff0000" or "#ffffff"
        )
    end
end
```

## 六、现有唯一正式版候选实现的错误已证实

原候选实现与51槽原始指令存在以下差异：
1. 把原型本身错误写成两个参数的工厂函数；原型本身应是`(buttonKey, toggled)`，4项依赖来自upvalue。
2. 把H[3]错误当成整个MainLeftBottom表，再访问`.b`；原始H[3]已经是`MainLeftBottom.b`。
3. 命中配置后提前return；原始控制流继续遍历剩余配置和后续组。
4. 原始函数先写入所有匹配配置的toggled，之后才查按钮；原候选只写第一个匹配配置。
5. 原始函数还要求匹配配置的`toggle`字段为真才更新GUI；原候选没有该提前结束条件。

这些差异现已由完整51槽指令和父级捕获描述符证实，不再属于常量推测。
