## 二、槽55–77原版控制流闭合

### 1. 获取苹果物品索引（槽55–59）

- 槽55 Opcode361融合消费槽56、57：从常量表装载`SL`，准备`SL.GetMetaValue`方法及receiver，并装载参数`ITEM_INDEX_BY_NAME`。
- 槽58装载常量`苹果`。
- 槽59 Opcode209调用方法并将结果写入寄存器1。

得到的调用为：

```lua
itemIndex = SL:GetMetaValue("ITEM_INDEX_BY_NAME", "苹果")
```

注意：这段原版指令没有对`itemIndex`再调用`tonumber`。

### 2. 获取苹果库存数量并转换（槽60–69）

- 槽60装载全局`tonumber`。
- 槽61–62准备`SL:GetMetaValue`方法。
- 槽63装载`ITEM_COUNT`，槽64装载字符串`苹果`。
- 槽65调用`SL:GetMetaValue("ITEM_COUNT", "苹果")`。
- 槽66调用`tonumber`，结果写入寄存器2。
- 槽67 Opcode325检查寄存器2真值，期望值为true。
- 若转换结果为nil，槽67跳过槽68，执行槽69将寄存器2设为0。
- 若转换结果有值，槽68 Opcode388跳转；按循环尾后置递增，实际从槽70继续，跳过默认值写入。

因此库存值等价于：

```lua
count = tonumber(SL:GetMetaValue("ITEM_COUNT", "苹果")) or 0
```

这里传给`ITEM_COUNT`的是物品名称`"苹果"`，不是前面取得的`itemIndex`。

### 3. 库存与索引条件、实际使用（槽70–77）

- 槽70 Opcode358检查寄存器1中的`itemIndex`是否为真值，期望值为false。
- 索引不存在时执行槽71跳转，实际越过使用调用区间。
- 索引存在时跳过槽71，进入槽72。
- 槽72 Opcode311执行比较分支：`(0 < count) ~= false`。当`count > 0`时跳过槽73，进入槽74；否则执行槽73跳转，跳过使用调用。
- 槽74–75准备`SL:UseItemByIndex`方法与receiver。
- 槽76将前面取得的`itemIndex`复制到调用参数寄存器。
- 槽77 Opcode123无返回值调用。

原版分支等价逻辑：

```lua
local itemIndex = SL:GetMetaValue("ITEM_INDEX_BY_NAME", "苹果")
local count = tonumber(SL:GetMetaValue("ITEM_COUNT", "苹果")) or 0

if itemIndex and count > 0 then
    SL:UseItemByIndex(itemIndex)
end
```

## 三、与唯一正式版当前辅助函数的差异

唯一正式版当前`TryUseAppleItem_11_16()`存在两处与原版指令不一致：

1. **索引值被额外转换**：正式版对`SL:GetMetaValue("ITEM_INDEX_BY_NAME", "苹果")`的返回值调用`tonumber`；原版直接保留返回值并检查其真值。
2. **库存查询参数不一致**：正式版调用`SL:GetMetaValue("ITEM_COUNT", itemIndex)`；原版传入的是字符串`"苹果"`。

原版明确支持的行为是：用物品名称获取索引；再用物品名称读取数量；数量经`tonumber`转换并以0作为缺省；只有索引存在且数量大于0时才调用`UseItemByIndex(itemIndex)`。
