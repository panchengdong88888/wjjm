# 11.16 项目说明与恢复规则

## 文件清单

| 文件 | 用途 | 是否可修改 |
|---|---|---|
| `MainLeftBottom 11.16原版.lua` | 原始输入，唯一原始依据 | 否，只读 |
| `MainLeftBottom_11.16_明文.lua` | 唯一明文源码输出 | 是，持续增量更新 |
| `AI接续入口与当前进度.md` | 每个AI对话的强制入口和任务规则 | 是 |
| `源码恢复进度账本.md` | 唯一进度记录、下一任务和审计记录 | 是 |
| `函数状态.csv` | 每个函数/原型的恢复状态 | 是 |
| `原型索引.json` | 原型层级、ID、指令量、捕获和函数身份索引 | 是 |

## 工作原则

1. 先分析11.16自身，不预设它与任何其他版本相同。
2. 以原始代码和可验证的静态证据恢复真实业务逻辑。
3. 唯一明文文件保持可读、可维护；分析过程和进度信息放在对应文档中。
4. 每完成一个明确单元就提交并更新状态，避免长时间只分析不落盘。
5. 进度按函数总数和实际完成状态计算，分母未建立前不报百分比。
6. 新对话只读取接续入口、进度账本和本轮相关资料，采用增量接续。
7. 所有文件都放在11.16目录，避免和11.9混淆。

## 官方框架开发文档（强制规则，2026-11-19新增）

### 文档位置

- GitHub 目标目录：`11.16/开发文档_新框架(3_40_xx)/`
- 目录索引：`11.16/开发文档_新框架(3_40_xx)/README.md`
- 原始压缩包来源：ChatGPT 文件库根目录 `/新框架(3_40_xx).zip`
- 压缩包名称：`新框架(3_40_xx).zip`，版本标识为 3.40.x。
- 注意：当前 GitHub 目录已建立索引，但45个Markdown正文文件尚未全部上传；在完成逐文件上传前，不得声称GitHub目录已包含完整文档。查阅正文时可从ChatGPT文件库中的原始ZIP读取。

### API 优先查文档规则

1. 在恢复11.16反汇编时，只要识别到疑似框架函数/API名称，必须先检索3.40.x开发文档（优先查 `SL.md`、`元变量.md`、`游戏事件.md`、`游戏触发.md)、`网络.md)、`GUILayout.md)、`GUI/`及 `itemData 数据结构说明.md`）。
2. 若文档明确收录该API，直接采用文档给出的准确名称、调用形式、receiver、参数顺序、参数类型、返回值及版本限制；不再反汇编或推导该官方API自身的内部实现。
3. 仍必须从11.16原始指令确认本项目业务代码的真实调用位置、receiver、实际参数、调用结果如何使用，以及调用前后的业务控制流。官方文档只替代API内部机制分析，不能替代11.16调用证据。
4. 若文档没有收录该名称，不得擅自认定为官方API；继续检查它是否为MainLeftBottom自身的业务函数、闭包辅助函数或全局业务变量。只有确属项目自身函数且需要恢复其实现时，才继续分析其原始指令。
5. 不得只凭函数名相似就套用文档条目；必须核对完整名称、大小写、版本条件和调用对象。文档未说明的参数/返回值标记为“待确认”，不得编造。
6. 例如 `GetMainPlayerID` 已确认属于框架API时，按文档签名直接使用；不得重复分析其底层实现。若业务代码调用 `global.gamePlayerController:GetMainPlayerID()`，仍须保留11.16证据所确认的receiver和调用位置。
7. 每个本轮首次使用的API，在分析记录中注明文档文件名和对应条目/标题；如有版本限制一并记录。后续遇到相同API可复用已记录结论，不重复查证。
8. 若GitHub文档目录尚未补齐，使用ChatGPT文件库原始ZIP中的对应文档；待完整上传后统一以GitHub目录作为长期引用位置。
