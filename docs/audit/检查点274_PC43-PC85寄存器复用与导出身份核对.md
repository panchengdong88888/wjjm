## 二、父寄存器连续衔接

结合检查点273的PC1-PC42身份核对，主装配影子寄存器初始值为：
- T[0] = rootModule.a
- T[1] = rootModule.b
- T[2] = rootModule.z
- T[3] = rootSource.timerState

随后PC43-PC85逐步建立T[4]至T[8]。影子表`rootRegisters`是恢复适配层表达，不声称原作者使用Lua table保存寄存器。

T[5]生命周期：
1. PC44暂存`_G`；
2. PC45执行`_G.log = T[4]`；
3. PC46创建ShowLocalNoticeByType并捕获T[0]；
4. PC47将T[5]覆写为ShowLocalNoticeByType。

T[6]生命周期：
1. PC48创建LuaSendMsg并捕获T[0]/T[4]；
2. PC51先写入`MainLeftBottom.a.LuaSendMsg`；
3. PC52覆写为ScheduleOnce。

T[7]在PC53创建Schedule。T[8]依序被PC54/56/58/60/62/64/68/71/74/79/83的闭包复用。

## 三、发现并修正的保护缺口

PC48-PC51原装配段在`make_LuaSendMsg`存在时才创建闭包；随后仅检查`rootModule.a.LuaSendMsg == rootPrototypes.LuaSendMsg`。如果来源工厂意外缺失，两侧均为nil时，该等值断言可能错误通过。

本批在PC51字段身份断言之前新增：

```lua
rootPrototypes.LuaSendMsg = requireRecoveredClosure(
    "LuaSendMsg", rootPrototypes.LuaSendMsg
)
```

这样会在来源工厂缺失时立即失败，不会让缺失的必需闭包以nil通过。
