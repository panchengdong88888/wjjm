# 检查点282：根模块固定参数入口回归修正

日期：2026-11-11

基线：检查点281

## 一、发现

继续核对根模块PC1-PC412时，检查PC297-PC315的配置文件包装链，发现检查点279整理函数时引入了两个参数入口回归：

| 原型 | 固定参数数 | 现有候选错误写法 | 修正后的入口 |
|---|---:|---|---|
| root.children[2] GetWritablePath | 1 | `function(...) local path = ...` | `function(path)` |
| root.children[9] ReadNumericConfig | 1 | `function(...) local fileName = ...` | `function(fileName)` |

## 二、证据

检查点235已通过原始VM执行器 `M()` 证明：原型tuple[3]记录固定参数数量；调用帧中前N个实参进入固定参数表T，超出N个的实参进入额外参数表X。因此旧dump字段名 `vararg`/`vararg_flag` 不应直接解释为Lua源码必须使用 `...`。

原型总索引确认两个函数的 `fixed_param_count=1`。对应PC调用关系也一致：

- root PC297创建GetWritablePath；调用时传入路径参数，函数PC7读取固定参数T[0]，PC8执行 `writablePath .. path`。
- root PC298-PC299创建ReadNumericConfig并捕获GetWritablePath；函数PC5-PC7读取固定文件名参数并传给捕获的GetWritablePath。没有读取额外参数的活动路径。
- AnonymousHelper_49/33分别把固定文件名传入ReadNumericConfig；不要求ReadNumericConfig将其当作vararg读取。
