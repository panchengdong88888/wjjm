# 检查点202：Attach_UITop调用形态与Nested_Anonymous捕获用途复核（更正稿）

日期：2026-11-10（Asia/Singapore）

## 更正说明

本报告初稿将调用指令中的B字段误读为参数数量。根据反汇编伪代码 `U(T,A+1,B)`，U按起始下标和结束下标展开，B是结束下标。因此此前“七个显式实参”的结论不成立，现以检查点203更正稿为准。

## 正确的调用形态

- PC178-PC180：取得NPCStorageProxy.RequestStorageData；PC180为 `OP_358 A=6 B=7`，实际展开 `T[7]..T[7]`，即一个实参T[7]。
- PC181-PC183：取得GUI.Attach_UITop；PC183为 `OP_068 A=6 B=7`，同样只展开一个实参T[7]。
- 两次调用都传递同一个T[7]，不能称为七参数调用。

T[7]在当前原型PC133的OP_233多返回值调用处被写入T[5]..T[7]；PC143的OP_339只写T[8]..T[9]。因此PC133是调用前最后一个静态可见的T[7]写入点，但其运行时值仍未确认。

## Nested_Anonymous用途级判断

Nested_str使用T[0]作为dialogParams.str初始文本；数字校验成功后调用T[1]并传入number；错误提示闭包调用T[2]并传入固定错误文本。这些只能说明用途，不代表调用端槽位和值类型已闭合。

## 当前结论

- T[0]/T[1]/T[2]用途级判断保留；调用端来源仍未闭合。
- unknown哨兵与GUI宿主方法语义仍未知。
- 统计维持普通Lua草稿72、完整静态恢复103/110、运行时验证0。
- 详细调用链和本次更正见检查点203审计报告。
