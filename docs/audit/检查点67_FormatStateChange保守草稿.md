## 已确认
1. 常量包含`string`、`format`、`状态切换: %s -> %s`。
2. PC1-PC7形成格式化调用：取`string.format`，传入固定格式串，并将T[3..5]区间交给格式化函数；OP_252把返回结果写回临时参数槽。
3. PC8调用捕获的`UPVALUE_0`。
4. PC9执行`UPVALUE_1 = R0`。
5. 根原型PC181创建该闭包，捕获数2；PC182/183的捕获描述依次为当前根函数R4、R14。因此本函数`UPVALUE_0 <- root R4`，`UPVALUE_1 <- root R14`。

## 尚未闭合
- 根函数R4/R14在PC181时的业务语义名称未由本批完整追踪。
- `vararg_flag=1`与VM参数表T[0..]的具体固定参数/变参边界仍需结合解释器参数初始化规则核验。
- PC8调用UPVALUE_0的参数区间由OP_093的T区间语义决定；草稿以格式化文本作为主要业务参数，但不宣称作者原始参数边界已完全还原。
- PC9把R0写入UPVALUE_1；草稿以`select(1,...)`表示待确认的首参数来源，需再核对R0与函数参数表映射。
- 因上述参数槽位仍有假设，本批只记为保守草稿，不升级完整静态恢复；未运行时验证。
